# Hydra Station: End-to-End Implementation Roadmap

This roadmap synthesizes the `hydra-station-master-plan.md` and the subsequent architectural reviews into a linear, step-by-step execution plan. It is designed to be built iteratively, ensuring each layer is stable before adding complexity.

---

## Phase 1: Infrastructure & Base Scaffolding
**Goal:** Get the core services running and communicating with minimal memory footprint.

1. **Docker Compose Setup**
   - Create `docker-compose.yml` defining `backend` (FastAPI), `postgres`, and `redis`.
   - Apply strict resource limits (e.g., 768MB for backend, 1GB for Postgres, 256MB for Redis) to ensure it fits the 4GB/1-core ceiling.
2. **FastAPI Skeleton**
   - Setup project structure: `api/`, `agents/`, `db/`, `backup/`.
   - Create a basic "Hello World" health-check endpoint.
3. **Database Connection**
   - Configure **async** SQLAlchemy with `asyncpg` to connect to Postgres.
   - Set up database migrations (e.g., Alembic).

---

## Phase 2: Core Data Layer & Security
**Goal:** Establish multi-tenancy, user management, and secure routing.

1. **Schema Definition**
   - Create the `users` table (`id`, `username`, `password_hash`, `role`).
   - Create business tables (`expenses`, `stock_trades`, etc.), ensuring every table has a `user_id` foreign key.
   - Create an `agent_runs` table for telemetry.
2. **Authentication & Authorization**
   - Implement JWT-based login (`/auth/login`).
   - Create dependency injection guards: `get_current_user` and `require_admin`.
   - Seed the initial admin user ("JD") securely via startup script or env vars.

---

## Phase 3: The Agentic Brain (LangGraph)
**Goal:** Build the agent workflows as code, ensuring persistent memory and security.

1. **Agent Setup**
   - Define the `Router` agent and specific sub-agents (e.g., `expense_agent`, `stock_agent`) using LangGraph.
2. **Persistent Checkpointer Configuration**
   - Install `langgraph-checkpoint-postgres` and configure `AsyncPostgresSaver`.
   - **Crucial Security Step:** Set `LANGGRAPH_STRICT_MSGPACK=true` to prevent unsafe deserialization of agent memory payloads from the database.
3. **Tool Binding**
   - Equip agents with tools to read/write to the database (using async DB sessions).
   - Ensure tools automatically filter operations by the `user_id` extracted from the JWT context.

---

## Phase 4: Asynchronous Processing (The Redis Queue)
**Goal:** Process background tasks safely without blocking the FastAPI event loop or requiring a 4th container.

1. **Custom Asyncio Worker**
   - Instead of Celery, write a lightweight `asyncio` task loop inside FastAPI's `@asynccontextmanager` lifespan event that polls Redis for new jobs (e.g., incoming SMS notifications).
2. **Non-Blocking Execution**
   - Ensure the worker exclusively uses **async** clients (`httpx.AsyncClient` for external APIs, async LLM clients, and `asyncpg` for DB) to prevent stalling the FastAPI event loop.
3. **Error Handling & Telemetry**
   - Ensure failed jobs are logged to the `agent_runs` table for visibility.

---

## Phase 5: Visibility & Backup Interfaces
**Goal:** Add observability and prepare for future data portability.

1. **The Agent Console (Static UI)**
   - Create a single HTML file using `mermaid.js` via CDN to visualize the agent graph (`graph.get_graph(xray=True).draw_mermaid()`).
   - Serve this file from a FastAPI endpoint returning an `HTMLResponse`, protected by the `Depends(require_admin)` guard.
   - Expose an `/api/agent-runs` endpoint for the UI to display recent execution logs.
2. **Backup Provider Interface**
   - Define the `BackupProvider` Python protocol (interface).
   - Implement `LocalFileBackupProvider` to dump DB tables to a mounted JSON volume via an `APScheduler` cron job inside the FastAPI process.
   - *(Google Drive integration remains deferred for Phase 1.5).*

---

## Phase 6: Client Integration
**Goal:** Connect the Android Shell to the Backend.

1. **API Contract Alignment**
   - Ensure the FastAPI routes expect the exact JSON payloads generated by the Android `NotificationListenerService` and `SpeechRecognizer`.
2. **Server-Driven UI (SDUI)**
   - Finalize the JSON schema that the backend returns to the Android app for rendering dynamic components via Jetpack Compose.
3. **End-to-End Testing**
   - Test the full flow: Voice Input -> Android -> FastAPI -> Redis Queue -> Async Worker -> LangGraph Agent -> Postgres -> SDUI Response back to Android.
